# M8: ejecución de CI en el fork del usuario

Fecha: 2026-09-25. Destino comprobado: `origin=https://github.com/lalomalvi/OpenCADStudio.git`; `upstream` es el repositorio del autor y no se usó. El [PR draft #1](https://github.com/lalomalvi/OpenCADStudio/pull/1) permanece abierto y sin merge.

Tras publicar el candidato M8, `gh pr checks 1` no reportó checks y la API de Actions mostró cero runs históricos, aunque permisos y workflows figuraban habilitados/activos. Se despachó explícitamente el workflow existente [Python host check, run 36106977767](https://github.com/lalomalvi/OpenCADStudio/actions/runs/36106977767) sobre `ce02ed73daab20109b01873c0fc15b73db22cfaf`. **Completed/success**: jobs Linux (15m11s) y Windows (22m1s) aprobaron pruebas de API/plugin/modelo y el paso `Host tests over real IPC`. Se observó el mismo ID hasta estado terminal, sin relanzar la intención.

`ci.yml` se amplió en `d84fb8d8603a85650e85152b7f396bcdb4411f5d` para aceptar push de `codex/mcp-*` y `workflow_dispatch` además de PR. El push de ese commit no produjo un run automático observable. Se disparó manualmente [Tests, run 36107070964](https://github.com/lalomalvi/OpenCADStudio/actions/runs/36107070964) sobre ese SHA: **completed/success**, job `test` y paso `cargo test --workspace --locked` aprobados en Ubuntu 22.04 en 9m47s. Esto resuelve el gate de ejecución Rust en CI para ese código; el primer intento local Windows que agotó paginación permanece fallido y documentado en [M8-RELEASE-CANDIDATO-LOCAL-V1.md](M8-RELEASE-CANDIDATO-LOCAL-V1.md).

Cada workflow manual queda vinculado a su SHA de ejecución; ninguno debe presentarse como check automático aprobado del PR si `statusCheckRollup` sigue vacío o el HEAD cambia. Para un HEAD final distinto, despachar `ci.yml` una vez sobre ese HEAD y verificar conclusión y `headSha`. No hacer merge mientras M7/M8 y demás gates sigan abiertos. La ausencia de auto run se registra como comportamiento observado del fork, sin atribuir causa no verificada.
