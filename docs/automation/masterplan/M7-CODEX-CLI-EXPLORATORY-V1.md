# Luna mediante Codex CLI: desarrollo exploratorio

Esta vía usa el plan de Codex sin clave API: `codex exec`, modelo solicitado `gpt-6-luna`, esfuerzo `medium`, configuración de usuario ignorada, sesión efímera, sandbox de solo lectura y una imagen adjunta. El JSONL informa eventos y uso agregado, pero no entrega objeto Responses directo, identidad efectiva autenticada ni uso separado de un supervisor. Por eso el resultado se clasifica como **L3 exploratorio parcial**, sin promover G0/G10 ni aceptación M7.

El primer caso fue un detalle rectangular con dos cotas explícitas. Se congelaron localmente imagen, prompt, criterio, CLI y hashes antes de una única llamada al modelo. La salida PlanSpec-1 pasó JSON estricto, compilación, medida y cierre de cuatro líneas. La primera GUI CAD creó DWG y PNG pero no salió dentro del plazo de cierre; solo se terminó esa GUI hija. Una segunda GUI reutilizó la misma salida del modelo, detectó el documento `dirty`, guardó y salió tras `QUIT`. Ambos intentos y sus recibos permanecen en `target/mcp-cli-development/`; no se reescribió el fallo ni se llamó de nuevo a Luna.

Una copia del DWG fue abierta por AutoCAD Core Console: `AUDIT` 0/0, unidades métricas y cuatro LINE. El comparador local verificó cuatro handles y sus extremos con tolerancia `1e-6`; una copia negativa con un extremo modificado falló 3/4. El alcance era el detalle seleccionado, no la lámina completa. Los prompts, planos, DWG, PNG, eventos y medidas de fuente son evidencia local ignorada por Git. Véase [M7-CINCO-MUESTRAS-V1.md](M7-CINCO-MUESTRAS-V1.md) para el pase posterior autorizado por el usuario.
