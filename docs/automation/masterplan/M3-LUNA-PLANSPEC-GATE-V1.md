# M3/M4 — gate de PlanSpec desde salida Luna v1

La [respuesta de Responses API](https://developers.openai.com/api/reference/cli/resources/responses/methods/create) contiene items `output`, mensajes y contenido `output_text`. `luna_planspec_gate.interpret_response` toma el objeto directo **en memoria**, valida el recibo de identidad/uso M3 y admite un único mensaje final del asistente con un solo `output_text`. Ignora items de razonamiento sin leerlos; rechaza llamadas a herramientas, mensajes adicionales, contenido de rechazo, mensajes no finales, discrepancia con `output_text` agregado y texto mayor a 1 MB.

El texto debe ser JSON estricto: sin Markdown, constantes no finitas ni claves duplicadas. El caller fija de antemano las versiones PlanSpec permitidas y el máximo de comandos. El gate ejecuta `planspec.dry_run` sin tocar CAD; exige `executable=true`, sin capacidades `unsupported` ni `quality_blockers`, y comandos dentro del máximo. Devuelve PlanSpec/compilado **solo en memoria**, hash canónico del plan, hash de comandos y recibo sanitizado de respuesta. Un fallo devuelve error genérico sin eco del contenido privado. El modelo no decide si su propuesta pasa.

L0 con fixtures sintéticos: un plan v8 de puerta intermedia despejada compila 18 entidades de forma determinista; el caso con mobiliario invasor se rechaza antes de CAD. También se rechazan duplicado `units`, NaN, Markdown, versión incorrecta, mensaje extra, llamada a herramienta y texto agregado contradictorio. No hay llamada Luna real ni enlace completo a ejecución/guardado/supervisor; G0–G10, L3 y L5 siguen pendientes. El callback futuro debe invocar este gate después de `request_luna_once` y antes de cualquier `ocs_execute`.
