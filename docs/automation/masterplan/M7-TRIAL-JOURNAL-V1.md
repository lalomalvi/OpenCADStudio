# Journal de intentos M7 para baseline y candidato

`reserved_trial.TrialJournal` enumera implícitamente 36 casillas: seis imágenes × tres repeticiones × dos brazos (`baseline`, `candidate`). Ambos brazos fijan el mismo modelo solicitado, esfuerzo y huella de hardware; cada brazo puede fijar su propio protocolo y binario CAD. El registro inicial vincula los SHA de cohorte, oráculos, protocolos y binarios. Antes de reservar o reconciliar un intento se vuelve a ejecutar `verify_ready` sobre las seis imágenes y los seis oráculos. Un cambio deja el journal en estado de fallo cerrado.

`reserve(arm, case_id, repetition, request_id)` escribe y sincroniza a disco una intención con el hash del ID privado **antes** de invocar al modelo. El consumidor debe invocar al modelo una sola vez después de recibir `reserved`. Una pérdida de respuesta deja la casilla pendiente; no se reserva otra hasta reconciliar el mismo ID mediante `record_result`. `uncertain` consume la casilla sin reinterpretarla como éxito; un nuevo intento exige otro protocolo/corte congelado y conserva el denominador original. `record_result` es idempotente si se repite exactamente el mismo resultado. Un candado de archivo serializa escritores; un hash encadenado detecta cambios en registros anteriores. El journal omite rutas privadas, prompts, respuestas y contenido de imágenes.

Los resultados registran `completed`, `failed`, `partial` o `uncertain`, modelo efectivo declarado, ruta relativa y hash de un JSON de evidencia bajo el directorio del run. El archivo se vuelve a hashear al reabrir el journal; un cambio posterior falla cerrado. `completed` significa que el intento produjo evidencia y que la identidad declarada coincide con el modelo solicitado; **no** significa que G0–G10, calidad CAD o L5 hayan pasado. La identidad efectiva y el contenido semántico del archivo aún requieren verificación contra telemetría/artefactos de proveedor y motor. La API no llama al modelo ni a CAD; un runner real debe usarla como gate obligatorio. Las pruebas actuales son L0 sintéticas, no una evaluación de imágenes reservadas.

La cuenta y el estado se consultan con `snapshot()`; una casilla consumida jamás se reabre con un ID nuevo. Antes de ejecutar M7 real faltan: seis imágenes/oráculos revisados, integración con el invocador Luna y supervisor, uso medido, resultados CAD independientes, revisión humana y comparación estadística limitada por muestra.
