## Findings and responsibility

The README's download buttons targeted upstream. It advertised signed Windows
packages without verifying fork signing, and the inherited MSI installs
per-machine with upstream's identity. Those are product/documentation defects.
Fork releases are absent; that is a distribution gap, not proof of an inability
to compile or of a missing Rust installation on another agent's host.

Rust is installed and on PATH **on this audited host**. The earlier agent's
host/tool inventory is not available, so its claim cannot be retrospectively
disproved. Stopping after cloning, skipping conventional tool locations and
failing to complete a supported source route are operational agent failures
when prerequisites and authorization permit proceeding.

## Implemented gates and checks

- `scripts/desktop.ps1` / `desktop-macos.sh` → one standard-library Python
  lifecycle: diagnose, download, build, package, install, open, path, mcp, verify.
- No tool installs are implicit. Installed-but-off-PATH is distinguished from
  missing tools. Cargo's artifact message identifies the actual absolute output.
- Immutable package-hash installation slots preserve prior work. Package origin,
  architecture, all payload hashes and actual CLI metadata are checked on every
  resolution. Download/hash/extraction failures cannot become success.
- The existing MCP smoke suite gained bounded requests, clean EOF/stdout checks
  and negotiation of all supported legacy versions; modern discovery and the
  existing four-tool/schema checks are reused.
- GUI acceptance correlates the installed executable and PID to its private
  session, requires GUI mode and a rendered PNG; Windows also requires a visible
  native window. CAD mutations are confined to the owned synthetic profile.
- macOS LaunchServices acceptance uses NSWorkspace to open the exact `.app`,
  validates the launcher/child GUI relationship and rendered capture.
- Native CI builds, installs outside checkout under a path with spaces, tests
  repeat installation/resource failure, runs MCP, GUI, synthetic CAD and (Mac)
  LaunchServices checks, then exports reviewed packages and selected evidence.
  Private automation descriptors/tokens are excluded from artifact upload.
- Release preparation handles an empty fork and closes notes files before gh
  reads them on Windows. Fork weekly publication is no longer inherited cron.
  The fork release workflow calls the verified package workflow instead of
  uploading inherited upstream MSI/DMG assets. No workflow or release was run
  remotely and no changes were pushed in this campaign.

## Remaining external gates

macOS ARM64 and Intel must run the new workflow or the platform guide on real
native hosts. Script/static validation is not native platform support evidence.
Publicly trusted macOS downloads need an actual Developer ID identity and notary
Keychain profile; restricted Windows deployment may need Authenticode credentials.
Publication requires a clean reviewed commit, native green evidence, an approved
tag/release and operator authorization. Source changes/packages stay local.
